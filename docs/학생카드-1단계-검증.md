# 학생 카드 1단계 구현·검증

2026-10-23. 기준 브랜치 `feature/expression`, 작업 브랜치 `feature/student-card`.

## 구현한 범위

- 상단 학생 칩(출석·감정 완료 표시), 공간 부족·9명 이상이면 학생 목록 단추, 전역 빠른 기록 진입점.
- 학생 카드 앞면 자동 집계, PIN 뒤 누가기록 목록·분류/공유 필터·개별 수정·삭제·학생 정보.
- PIN 네 자리 두 번 입력, PBKDF2-SHA256 100,000회, 5회 실패 시 60초 대기, 복구 열쇠 확인 후 새 PIN. 창을 닫거나 3분간 활동이 없으면 다시 잠금.
- 빠른 문장 즉시 저장, 여러 학생 묶음, 자유 입력, 500ms 자동 반영, 10초 되돌리기, ABC·강도·분·도움 수준·공유.
- 설정의 빠른 문장/ABC 보기 추가·삭제·순서 변경. 학생은 명단에서 빼도 보관하고 보관 목록에서 카드를 열 수 있음.
- IEP 자료 형식·store·계산 함수만 준비. IEP 편집·목표 연결·인쇄·학생 완전 삭제는 제외.

## 저장 형식

- `SCHEMA_VERSION`과 IndexedDB 버전 1 → 2.
- `notes`, `ieps` store와 `byStudent` 복합 인덱스(`classId`, `studentId`) 추가.
- AppData: `studentNotes`, `ieps`, `notesConfig`, `expr`, 선택값 `recoveryKey` 추가.
- kv의 `expr:<학급>` 전체가 백업에 포함됨. PIN 해시는 백업에 포함하지 않음.
- 예전 백업은 새 항목을 빈 값·기본 설정으로 채움. 복구 열쇠가 같으면 현 PIN 유지, 다르면 제거.
- 저장 도중 동기 오류에도 트랜잭션을 취소하도록 공통 저장 창구 보강.
- 개인정보처리방침에 민감 기록·암호화하지 않는 화면 잠금·백업 주의사항 반영. 새 외부 통신이 없어 CSP는 변경하지 않음.
