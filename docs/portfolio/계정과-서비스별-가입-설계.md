# 공개 로컬 버전과 개인 클라우드 설계

2026-10-24 · 개인용 자동 저장 구현. 운영 배포는 별도.

## 현재 결정

이 문서는 기존 공통 회원·서비스 가입 설계를 대체한다. 허브 회원 자동 승계, 아침교실 공개 회원가입, 다교사 클라우드 모집은 더 이상 구현하지 않는다.

- 공개 아침교실: 가입·교사 인증 없이 기기 내 저장, 파일 백업·복원 유지.
- 제작자 개인 클라우드: 서울 `kyungmin-main-seoul` 프로젝트만 연결 대상으로 사용한다. 프로젝트 참조는 `pbpkoumwdjjciayxpbti`, 리전은 서울(ap-northeast-2)이다.
- `special_edu_hub`의 회원·트리거·테이블·Google 설정은 변경하지 않는다. 허브 회원에게 개인 클라우드 권한을 주지 않는다.
- 다른 운영자는 자신의 프로젝트·키·허용 계정을 구성한다. 제작자의 저장소를 기본 연결값으로 배포하지 않는다.
- 기존 서울 프로젝트에도 다른 앱 테이블이 있으므로 기존 members/admins/학생 테이블을 재사용하지 않는다. 아침교실 전용 스키마·비공개 버킷·정책을 추가하는 방식으로 별도 검토한다.

## 개인 인증과 연결 상태

사용자가 지정한 소유자 이메일의 계정이 서울 프로젝트에 존재함을 읽기 전용으로 확인했다. 해당 계정에는 Google identity가 아직 없다. 이메일·사용자 UUID는 공개 설계 문서에 기재하지 않는다.

개인 클라우드 활성화에는 본인의 Google 로그인과 계정 연결 확인이 필요하다. 기존 계정이나 identity를 임의 수정하지 않는다. 이메일이 같다는 이유로 다른 계정을 수동 병합하지 않는다. 기존 프로젝트의 Google 공급자와 callback 설정을 읽기 점검한 뒤 기존 앱을 유지하며 추가해야 한다.

로그인 후 검증된 Auth UUID 하나를 서버의 아침교실 전용 소유자 허용 목록에 등록한다. 화면의 이메일 비교·숨겨진 버튼·URL만으로 제한하지 않는다. 허용 목록은 일반 사용자에게 수정 권한을 주지 않는다. 모든 테이블/RPC/파일 접근과 업로드 허가는 소유자 또는 제한된 학생 binding을 검사한다. 학생 QR은 자기 활동 결과 제출만 가능하고 교사 자료 조회는 불가하다.

공개 빌드는 클라우드 비활성, 개인 빌드는 별도 환경 구성으로 활성화하는 방식을 권장한다. 개인 배포 URL을 안다고 접근 권한이 생기지는 않는다. 관리자 비밀키는 브라우저·Git 저장소에 넣지 않는다. 프로젝트 키가 공개 가능한 키여도 RLS를 대신하지 않는다.

서울 프로젝트에 mc_private_owners와 mc_private_snapshots를 추가했다. 기존 소유자 UUID만 허용 목록에 등록했고 다른 앱 테이블은 변경하지 않았다. 스냅샷은 소유자당 1개, 최대 10MiB다. 익명 접근 차단과 다른 UUID의 조회 차단을 확인했다. Google 공급자는 활성화되어 있지만 본인의 실제 Google 로그인은 아직 확인하지 않았다. 공식 SDK 기반 로그인·저장 화면을 연결했다. 자동 동기화는 개인-서버-설치.md의 최신 정책을 따른다. 외부 앱 결과 수신은 아직 포함하지 않는다.

## 저장과 기존 자료

개인용은 허용된 소유자가 로그인하고 해당 기기에서 자동 저장을 직접 켜면 자동 저장을 시작한다. 서로 다른 기존 자료는 백업 후 명시적으로 선택한다. 관리에서 자동 저장을 끌 수 있다. 얼굴 사진은 잘라낸 결과만 선택적으로 올리고 원본은 보내지 않는다. 결과물은 비공개 파일로 저장한다. 로컬 모드에는 네트워크 의존성을 추가하지 않는다.

[공통 연동 규약](./공통-연동-규약.md)의 학생 ID·binding·중복 방지·수신증 원칙은 개인 서버에도 적용한다. 다교사 tenant 구조는 타인의 자가 운영에서 확장 가능한 계약일 뿐 현재 제작자 클라우드의 공개 회원 기능이 아니다.

## 오픈소스 공개 준비

공개 랜딩에는 현재 가능한 로컬 기능과 직접 운영 확장 계획을 구분한다. 오픈소스 라이선스가 확정되고 이미지·글꼴·의존성 재배포 권한, Git 이력의 비밀정보·학생 자료 검사를 마치기 전에는 자유 재배포가 이미 허용된 것으로 안내하지 않는다.

후속 작업: 라이선스 선택, 자가 운영 설치 문서, 빈 환경 설정 예시, 소유자 초기 설정, DB 마이그레이션·권한 시험, 백업·복구 절차. 개인 이메일·실사용 학생 데이터·토큰이 예시 파일에 들어가지 않게 한다.

## 구현 순서와 검증

1. 기존 서울 앱에 영향을 주지 않는 별도 가상 환경에서 개인 인증·소유자 허용 목록 설계.
2. 소유자의 실제 Google 로그인 확인 후 계정 UUID 확정. 다른 계정 로그인은 자료 접근 거부.
3. 아침교실 전용 저장소·비공개 버킷·API 추가와 소유자/학생 권한 시험.
4. 이미지 압축·용량 예약·전송 대기·백업 복구 시험.
5. 개인 학급 한 개로 시작, 공개 빌드는 클라우드 설정이 없는지 확인.

기존 허브 회귀를 요구하는 공통 가입 마이그레이션은 폐기했다. 서울의 기존 앱은 회원/테이블/정책 변경 없이 유지하는 것을 우선한다. 실제 설정 변경·인증·학생 전송은 이번 문서 수정에 포함되지 않는다.

현재 미리보기는 Git에서 제외한 `.env.development.local`로 개인 메뉴를 켠다. 공개 기본 빌드에서는 이 파일을 읽지 않는다. 개인 배포 전에는 CSP connect-src에 자신의 프로젝트 주소를 추가하고 정확한 OAuth 복귀 주소를 허용해야 한다. 기존 앱의 Site URL을 교체하지 않는다.
