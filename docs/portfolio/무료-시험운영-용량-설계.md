# 무료 시험 운영·이미지·용량 설계

2026-10-24 · 설계 초안. 아래는 초기 운영 기본값이며 코드·Supabase에 적용하지 않았다.

## 운영 범위

공개 아침교실은 가입 없이 로컬로 사용한다. 클라우드는 제작자 본인만 서울 프로젝트에서 사용하며, 다른 교사에게 슬롯을 배정하지 않는다. 기존 5학급 모집 계획은 폐기한다. 초기에는 본인 학급 1개로 시험한다. 다른 운영자는 자신의 저장소를 구축한다.

첫 시험은 이미지·텍스트 결과만 받는다. 영상·음성·PDF는 미지원으로 안내하고 원본 보관·내보내기 경로를 제공한다. 기존 허브 자료·설정·요금제는 변경하지 않는다.

## 초기 기본값

| 항목 | 설계값 |
|---|---:|
| 시험 학급 수 | 제작자 본인 1개 |
| 학급별 파일 | 누적 100MB |
| 아침교실 전체 파일 예산 | 초기 누적 100MB |
| 학급별 구조화 기록 | 논리 용량 10MB |
| 이미지 압축 목표 | 장당 200KB 이하 |
| 이미지 최종 업로드 상한 | 장당 500KB |
| 텍스트 결과 봉투 | UTF-8 50KB 이하 |
| 학급 용량 알림 | 70% 안내, 90% 정리 권유, 100% 추가 저장 차단 |

MB는 1,000,000바이트, KB는 1,000바이트로 계산한다. 매월 초기화되는 용량이 아니다. 파일 한도에는 얼굴·작품·썸네일·파생 이미지·보관 중인 이전 버전·미완료 예약을 포함한다.

DB 논리 용량은 서버에서 직렬화한 기록 크기로 계산하며 실제 Postgres 크기와 다르다. 인덱스·인증·이력·시스템 공간까지 포함한 실제 DB 사용량을 별도로 감시한다.

100MB는 200KB 이미지 약 500장이다. 학생 5명이 수업일마다 한 장씩, 월 20일 저장하면 약 5개월, 20명이면 약 1.25개월 분량이다. 얼굴·썸네일·다른 자료를 제외한 추정이며 무료 장기 보관을 보장하지 않는다.

## 조직 전체 예산과 개방 조건

서울 프로젝트와 조직 전체 사용량을 활성화 전에 확인한다. 과거 special_edu_hub의 측정치를 서울 프로젝트 잔여량으로 사용하지 않는다. 같은 조직의 허브와 서울 프로젝트가 무료 할당을 함께 사용할 수 있으므로 기존 서비스 사용량도 고려한다.

- 개인 파일 예산 100MB와 서울의 기존 앱·조직 전체 사용량을 합해 여유가 있을 때만 시작한다.
- 부족하면 새 업로드를 보류하고 기존 자료는 임의 삭제하지 않는다. 다교사 모집·개인 용량 확대 배정은 하지 않는다.
- 공식 할당 대비 70%에서 운영자 알림, 80%에서 개인 용량 확대 중단, 90%에서 해당 자원을 늘리는 요청을 보류한다. 플랫폼 제한이 더 이르면 플랫폼 기준을 따른다.
- 공식 수치는 청구 기간 평균일 수 있어 삭제 직후 잔여량이 회복된다고 표시하지 않는다. 실제 서비스 보관량·예약량과 공식 집계를 구분한다.
- 매일 실제 사용량과 원장을 대조한다. 확인이 오래됐거나 집계가 실패하면 개인 용량 확대 확대를 보류한다.
- 이미지 반복 조회도 전송량을 사용한다. 썸네일 지연 로딩·권한 내 캐시·변경분 동기화를 사용한다. 비용 때문에 파일을 공개로 바꾸지 않는다.
- 자동 업그레이드·초과 과금 허용은 하지 않는다. 유료 전환은 사용자와 별도 결정한다.

## 이미지 압축 흐름

1. 업로드 전에 기기에서 사진 방향을 바로잡고 해상도를 확인한다. 입력 보호 기준은 원본 20MB·2,400만 화소 이하로 두고 초과·디코딩 실패는 작은 JPG/PNG 재선택을 안내한다.
2. 긴 변 최대 1,600px로 줄이고 작은 이미지는 확대하지 않는다. WebP 우선, 미지원 환경은 JPEG, 투명 배경이 필요하면 WebP/PNG를 사용한다.
3. 품질 약 0.8부터 200KB 목표로 조절한다. 품질 0.6 또는 긴 변 1,000px까지 줄여도 큰 경우 미리보기를 제공한다. 글씨가 뭉개지는 압축을 자동 확정하지 않는다.
4. 읽을 수 있는 결과가 200KB를 넘더라도 500KB 이하면 확인 후 저장할 수 있다. 500KB 초과는 잘라내기·작은 이미지·기기 보관을 안내한다. 원본은 자동 삭제하지 않는다.
5. 필요한 썸네일만 긴 변 320px·목표 30KB 이하로 별도 생성하고 용량에 포함한다. 원본·불필요한 중간 크기는 업로드하지 않는다. 얼굴은 기존 320×320 잘라낸 결과만 대상으로 한다.
6. 재인코딩으로 EXIF·위치 메타데이터를 제거한다. 서버에서도 실제 형식·바이트·화소·디코딩을 검사한다. 확장자나 브라우저가 주장하는 크기를 신뢰하지 않는다. 업로드 허용 형식은 WebP/JPEG/PNG이며 SVG·애니메이션·원본 HEIC는 받지 않는다. HEIC를 기기에서 변환하지 못하면 안내한다.
7. 외부 교육 앱에도 같은 기준을 적용한다. 검사 실패·용량 초과로 필수 작품이 빠졌다면 정상 결과 저장으로 표시하지 않는다.

## 용량 예약과 저장

개념 자료는 class_quota, upload_reservations, artifacts, quota_events로 나눈다. 아직 테이블을 만들지 않는다.

- 서버가 검증된 교사 세션 또는 학생 binding으로 학급을 결정한다. 요청의 임의 학급 ID·할당량을 믿지 않는다.
- 실제 사용량 + 미완료 예약 + 요청 크기를 학급 한도와 서비스 전체 예산 모두에 대해 원자적으로 검사·예약한다. 여러 기기의 동시 요청이 남은 공간을 중복 사용하지 못하게 한다.
- 업로드 허가는 지정 경로·단일 파일·예약 크기·15분 만료에 묶는다. 서명 URL만으로 모든 제약이 보장된다고 가정하지 않으며 실제 업로드 경로에서 크기 초과·재사용·임의 경로 쓰기를 막는다.
- 실제 파일 크기 확인 뒤 예약을 사용량으로 옮긴다. 결과 영속 저장 뒤에만 수신증을 보낸다. 재전송은 같은 resultId로 멱등 처리한다.
- 만료·실패·고아 파일은 실제 객체 삭제 완료 후에만 사용량을 해제한다. 삭제 실패인데 숫자만 줄이지 않는다.
- 파일 교체 시 새 파일 검증까지 기존 파일을 유지한다. 일시적 이중 용량을 예약하며 실패하면 기존 결과를 보존한다.
- 휴지통·이전 버전을 보관하는 동안에도 용량을 계산한다. 학급 삭제·보관·재생성으로 남은 파일이 집계에서 사라지지 않게 전체 합계를 유지한다.
- 실제 객체와 용량 원장을 주기적으로 대조하고 불일치 시 운영자에게 알린다.

## 한도에 도달하면

관리 → 저장 공간에서 ‘이 학급 64 / 100MB’, 기록 용량, 항목별 사용량을 보여준다. 다른 교사의 사용 내역은 공개하지 않는다.

파일 한도에 도달하면 새 파일 업로드를 보류하고 기존 조회·내보내기를 유지한다. 텍스트는 해당 한도와 조직 예산이 남아 있을 때만 저장한다. ‘활동을 마쳤어요’와 ‘아침교실에 저장했어요’를 구분한다.

안내 예시: ‘학급 저장 공간이 가득 찼어요. 이 결과는 아직 전송되지 않았어요.’

미전송 자료는 가능한 범위에서 원래 학생 binding을 유지한 기기 대기열에 보관한다. 기기 저장도 실패하면 내보내기를 안내하고 보관 성공을 거짓 표시하지 않는다. 용량 초과에는 빠른 자동 재시도를 하지 않고 공간 확보 후 다시 전송한다.

오래된 작품을 자동 삭제하지 않는다. 교사가 백업·삭제 대상을 확인한다. 학급 비활성화만으로 파일을 삭제하거나 용량을 돌려주지 않는다.

## 백업과 시험

무료 플랜 자동 백업을 전제로 하지 않는다. 클라우드 파일과 기록을 함께 내보내고 복구하는 경로를 마련한다. 기존 로컬 JSON 백업에 파일 바이트가 자동 포함된다고 가정하지 않는다. 파일 URL만 담긴 내보내기는 완전한 백업이 아니다. 다른 교사 자료·토큰·QR 비밀은 포함하지 않는다.

개방 전 확인할 것:

- 태블릿의 회전 사진·투명 이미지·작은 글씨·큰 사진·HEIC 미지원·압축 실패.
- 압축 전후 가독성·크기, 원본 보존.
- 두 기기의 동시 마지막 용량 예약, 학급 한도와 전체 예산 초과 차단.
- 예약 만료·전송 중단·재전송·교체·삭제 실패 후 원장 일치.
- 한도 초과 시 미전송 표시, 원래 학생 귀속, 내보내기·재전송.
- 다른 학생·교사의 업로드·읽기·삭제·할당 변경 차단.
- 가상 학급으로 실제 DB 증가량·전송량 측정, 백업 복구 시험.
- 조직 공식 사용량 확인 후 개인 시험 시작.
