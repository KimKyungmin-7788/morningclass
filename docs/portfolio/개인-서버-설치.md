# 개인 서버 연결

## 현재 상태
공개 버전은 로컬 저장을 유지한다. GitHub 저장소는 공개되어 있지만 재사용 라이선스는 아직 정리 중이다.

서울 프로젝트에는 아침교실 전용 테이블과 소유자 정책만 추가했다. Google 제공자는 켜져 있다. 공식 SDK와 개인 서버 메뉴를 연결했다. 본인의 Google 로그인과 서버 저장·불러오기를 개발 미리보기에서 확인했다.

## 다른 운영자의 설치 순서
1. 자신의 Supabase 프로젝트를 준비한다. 제작자 프로젝트의 키를 복사하지 않는다.
2. `setup/private-cloud.sql`의 새 테이블 이름이 기존 테이블과 충돌하지 않는지 확인하고 적용한다.
3. 본인의 Google 로그인으로 만들어진 Auth 사용자 UUID를 관리자가 `mc_private_owners`에 등록한다. 허용 목록의 수정 권한을 사용자에게 주지 않는다.
4. `.env.personal.example`을 `.env.personal.local`로 복사하고 본인 프로젝트 URL과 공개 가능한 publishable key를 넣는다. 서비스 역할 비밀키는 넣지 않는다.
5. 개인용 빌드는 `npm run build -- --mode personal`, 공개용은 `npm run build`를 사용한다. 개인용 환경 변수를 공개 배포에 넣지 않는다.
6. 개인 배포의 CSP connect-src에 자신의 Supabase HTTPS 주소만 추가한다. 공개 vercel.json은 그대로 유지한다.
7. 기존 Auth Site URL을 바꾸지 말고 개인 앱의 정확한 `/app.html` 복귀 주소만 허용 목록에 추가한다. localhost도 별도 허용한다.

## 저장 방식
개인용은 허용된 소유자가 로그인하고 해당 기기에서 자동 저장을 직접 켜면 자동 저장을 시작한다. 기기 IndexedDB에 먼저 저장하고, 변경을 약 2초 간격으로 서버에 반영한다. 앱 진입·온라인 복귀·화면 복귀 및 사용 중 30초 간격으로 서버 revision을 확인한다. 내용이 같으면 다시 업로드하지 않는다. 공개 빌드는 클라이언트와 동기화 작업을 실행하지 않는다.

- 이름·잘라낸 얼굴 사진·활동·누가기록 등이 포함되며 PIN 해시는 제외한다. 소유자당 최신 스냅샷 1개, 최대 10MiB다.
- 새 기기가 완전히 빈 기본 학급이면 서버 자료를 자동으로 불러온다. 기존 자료가 서로 다른 첫 연결은 파일 백업 후 사용할 자료를 선택한다.
- 기기와 서버가 마지막 동기화 이후 모두 바뀌면 자동 덮어쓰기를 멈춘다. 기록 단위 병합은 하지 않는다.
- 서버 업데이트는 revision 조건으로, 로컬 불러오기는 IndexedDB 쓰기 세대 검사로 경쟁 변경을 막는다. 같은 브라우저의 탭들은 Web Locks로 전송을 직렬화한다.
- 입력창이 열려 있으면 자동 불러오기를 미룬다. 자동 불러오기 직전 로컬 사본과 명시적 서버 덮어쓰기 직전 서버 사본을 기기에 각각 1개 보관하고 내려받기를 제공한다.
- `_cloud:` 값은 기기별 동기화 기준·세대·사용 설정·복구 사본이다. 학생 자료 형식 v9는 유지하며, 이 내부 값들은 일반 백업/서버에 넣지 않는다. 백업 복원 시에는 기기의 내부 값을 유지한다.
- 네트워크/용량/권한 오류가 나면 기기 자료와 마지막 성공 기준을 유지한다. 이후 확인 주기에 재시도한다. 앱이 닫혀 있는 동안에는 전송하지 않으므로 닫기 전 상단의 저장 상태를 확인한다.
- 관리 → 개인 서버에서 자동 저장을 끄거나 로그아웃할 수 있다. 기존 허브, 인증 제공자 설정, RLS 정책, CSP 연결 대상은 변경하지 않는다.

외부 교육 앱의 이미지/텍스트 결과 수신, 학생 QR 발급, 포트폴리오 자동 누적은 별도 후속 구현이다. 현재 연결만으로 사용할 수 있다고 안내하지 않는다.

현재 미리보기는 Git에서 제외한 `.env.development.local`로 개인 메뉴를 켠다. 공개 기본 빌드에서는 이 파일을 읽지 않는다. 개인 배포 전에는 CSP connect-src에 자신의 프로젝트 주소를 추가하고 정확한 OAuth 복귀 주소를 허용해야 한다. 기존 앱의 Site URL을 교체하지 않는다.

서울 개인 배포용 CSP는 `vercel.personal.json`에 분리했다. 공개 배포는 기존 `vercel.json`을 사용한다. 개인 환경 변수는 Git에 넣지 않고 개인 배포 프로젝트에만 설정한다. 다른 운영자는 개인 설정의 Supabase 주소도 자신의 주소로 바꿔야 한다.

## 2026-10-24 실제 연결 검증

본인 Google 계정으로 미리보기에서 서버에 저장하고 다시 불러왔다. 시험 전 로컬 파일 백업과 서버 저장본의 data 전체가 일치했고, 복원 후 다시 내보낸 백업도 동일했다(변경 항목 0개). 실사용 자료를 시험용 내용으로 바꾸지 않았다. 서버는 최신 스냅샷 1개를 유지한다. 연속 confirm 대신 화면 내 복원 요약·백업 보관 확인·완료 알림을 사용한다. 검사 266개 및 공개 빌드 통과. 운영 배포와 별도 기기에서의 복원 시험은 아직 진행하지 않았다.

개인 배포에서는 급식·사전·그림 조회와 익명 집계 API만 기존 공개 아침교실 API로 전달한다. 학생 백업은 이 경로를 거치지 않고 개인 Supabase로 직접 보낸다. 기존 API 비밀키를 개인 프로젝트에 복사하지 않는다.

## 분리 배포 주소

- 공개: https://morningclass.vercel.app — VITE_PERSONAL_CLOUD=false, Git main 자동 배포.
- 제작자 개인용: https://morningclass-personal.vercel.app/app?nocount — 별도 Vercel 프로젝트 morningclass-personal. 동일 커밋의 임시 배포 폴더에서 vercel.personal.json을 vercel.json으로 사용해 배포한다. 개인 환경 변수는 해당 프로젝트에만 둔다.
- Google 복귀 허용 목록에는 https://morningclass-personal.vercel.app/app.html?nocount 를 추가한다. 기존 Site URL·기존 복귀 주소는 유지한다.
- 주소가 다르면 브라우저 저장소도 별개다. 처음 개인 주소에 접속한 뒤 로그인하고 서버 자료 불러오기로 시작한다. 빈 새 학급을 서버에 먼저 저장하지 않는다.
