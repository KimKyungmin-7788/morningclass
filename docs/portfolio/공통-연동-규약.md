# 아침교실 교육 웹앱 공통 연동 규약

> 운영 방향 변경(2026-10-24): 공개 버전은 로컬 전용이다. 클라우드 규약은 제작자의 서울 프로젝트 개인 운영 또는 각 개발자의 독립 자가 운영에 적용한다. 허브 계정 공유·공개 회원 모집은 하지 않는다. [현재 운영 설계](./계정과-서비스별-가입-설계.md)를 우선 읽는다.

상태: **설계 초안 0.1 · 서버/API/SDK 미구현**  
작성일: 2026-10-24  
대상: 학생 태블릿의 교육 웹앱, 결과 수신 서버, 아침교실 포트폴리오

이 문서는 앞으로 구현할 공통 계약이다. 예시 경로·필드가 현재 운영 API라는 뜻은 아니다. 첫 앱이나 특정 클라우드 제품에 종속되지 않는다. 구현 절차는 [웹앱 개발 지침](./웹앱-개발-지침.md)을 따른다. 서로 다른 저장소에서도 두 문서를 함께 제공한다.

## 1. 범위와 책임

학생 태블릿 → 결과 수신 서버 → 교사의 아침교실 순서로 결과를 모은다.

| 구성 요소 | 책임 |
|---|---|
| 교육 웹앱 | 활동 진행, 관찰한 결과 작성, 기기 내 전송 대기, 저장 완료 확인 |
| 연결 모듈 | 학생 연결, 결과 검증, 인증된 전달, 재전송 상태 제공 |
| 수신 서버 | 권한 검사, 학생 연결 확정, 중복 방지, 결과·첨부 저장, 수신증 반환 |
| 아침교실 | 권한 있는 교사에게 날짜별·활동별 결과 표시, 비교 조건 확인, 근거 기반 분석 |
| 교사 | 학생 연결 확인, 기록 검토, 종합의견 수정·확정 |

QR·링크·학급 코드·교사가 지정한 기기 등 접속 UX는 앱이 선택한다. 전달 규약과 권한 검사는 공통이다. 서버 구현 전에는 가상 어댑터를 사용하고 화면에 예시임을 표시한다.

현재 아침교실은 기기 내 저장 앱이다. 이 규약 작성만으로 실제 학생 자료의 외부 전송을 허용하지 않는다. 실제 연결 전에 서버·인증·자료 보관 정책을 확정하고 개인정보 안내와 관련 저장소 규칙을 갱신한다. 기존 얼굴 사진·출결·누가기록 전체 이전은 이 규약의 기본 범위가 아니다.

## 2. 용어와 식별자

| 필드 | 의미·규칙 |
|---|---|
| `tenantId` | 교사/학교의 자료 소유 범위. 서버가 인증 정보로 판별 |
| `learnerId` | 서버가 부여한 학생 고유 ID. 이름·번호를 ID로 쓰지 않음 |
| `classId` | 수행 당시 학급 ID. 학급 이동 뒤에도 과거 맥락 보존 |
| `appId` | 등록된 앱의 불변 ID. 표시 이름·도메인 변경과 별개 |
| `activityId` | 앱 안의 학습 활동 ID. 제목 변경과 별개 |
| `activityVersion` | 학습 목표·난이도·채점 방식 등 활동 정의의 버전 |
| `sessionId` | 한 번의 활동 실행 ID. 동일 세션의 정정과 새 실행을 구분 |
| `resultId` | 결과의 불변 ID. 최초 완료 시 생성, 재전송 때 재사용 |
| `bindingId` | 앱·학생·허용 범위·만료를 연결하는 서버 발급 참조 ID. 그 자체는 인증 비밀이 아님 |

ID 생성 형식은 구현 단계에서 하나로 확정한다. 전송 중 충돌 없이 생성할 수 있는 불투명 ID를 사용한다. 실제 이름·이메일·생년월일은 결과 봉투에 포함하지 않는다. `learnerId`도 연결 가능한 학생 정보이므로 로그·외부 분석 서비스에 노출하지 않는다.

## 3. 학생 연결과 인증

1. 교사가 로그인하여 학급과 참여 학생·활동을 지정한다.
2. 서버가 짧게 유효한 연결 수단을 발급한다. QR에는 원시 학생 정보나 장기 인증 토큰을 넣지 않는다.
3. 학생 기기는 연결 수단을 교환하여 제한된 학생 세션을 받는다. 학급 QR만 사용하는 경우 학생 배정은 교사 확인 또는 학생별 추가 연결로 확정한다. 이름 선택만으로 타인의 제출 권한을 얻을 수 없어야 한다.
4. 세션 권한은 지정 앱·학생의 제출과 자기 제출 수신증 확인으로 제한한다. 학급 전체 조회·다른 학생 조회·교사용 누가기록 조회 권한을 주지 않는다.
5. 서버가 `bindingId`를 검증하고 실제 학생·학급·소유 범위를 결정한다. 클라이언트가 주장하는 학생 ID를 신뢰하지 않는다.
6. 학생 변경·로그아웃·기기 반납 시 연결 상태를 명확히 해제한다. 전송 대기 결과의 소유 학생은 생성 당시 연결에 고정한다. 다음 학생으로 재배정하지 않는다.

정확한 인증 제공자, 세션 수명, 쿠키/토큰 보관 방식, 교사 확인 UX는 구현 전 확정한다. 브라우저에 관리자 비밀키를 넣지 않는다. CORS와 허용 출처 검사는 인증을 대체하지 않는다. 출처 간 창 메시지를 쓸 경우 양쪽에서 정확한 origin·source·메시지 형식을 검사한다.

### 학생 ID와 표시 이름

- `learnerId`는 아침교실의 학생을 가리키는 불변 식별자다. 이름·번호·학급이 바뀌어도 동일 학생의 ID는 유지한다. 동명이인은 서로 다른 ID를 가진다.
- 기존 기기 내 학생 ID와 서버 `learnerId`는 교사 소유 범위 안에서 명시적으로 매핑한다. 이름으로 자동 병합하지 않는다. 기존 외부 앱 명단도 교사가 최초 연결을 확인한다.
- 외부 앱의 학생 표시 이름은 인증된 연결 응답에서 제공한다. 학생이 다시 입력한 이름으로 대상을 바꾸지 않는다. 동명이인은 교사가 정한 번호·별칭을 함께 표시한다.
- 제출 봉투에는 기존처럼 `bindingId`를 사용한다. 서버는 인증된 세션과 binding에서 `tenantId`, `classId`, `learnerId`를 결정한다. 요청에 다른 학생 ID가 붙어도 대상을 변경하지 않으며 불일치는 거부한다.

### 학생별 QR 접속 흐름

1. 교사가 연결 앱·활동·학생을 선택하고 학생별 QR을 발급한다. 교사용 화면에는 이름과 번호를 함께 보여준다.
2. QR에는 허용된 접속 URL과 짧게 유효한 일회용 교환 코드만 넣는다. 이름, 원시 학생 ID, 장기 비밀키를 넣지 않는다. 코드는 앱·학생·활동 범위에 묶고 만료·사용·철회 상태를 서버에서 관리한다.
3. 태블릿은 코드를 서버에서 교환하여 제한된 학생 세션과 표시 이름을 받는다. 교환 코드를 URL·로그·분석 이벤트에 남기지 않게 처리한다. 만료·재사용·철회 시 교사에게 새 QR을 요청하도록 안내한다.
4. 앱에 ‘김민준 · 1번의 활동’처럼 대상을 표시한다. 학생이 다르면 활동을 시작하지 않고 교사에게 올바른 QR을 요청한다. 공용 기기에서 새 QR을 열면 이전 학생 세션과 분리한다.
5. 활동 완료 결과는 생성 당시 binding에 고정한다. 서버가 영속 저장한 수신증을 반환한 뒤 저장 완료를 표시한다.
6. 교사 아침교실은 인증된 소유 범위의 해당 `learnerId`로 결과를 조회해 날짜별·활동별 포트폴리오에 표시한다. 다른 동명이인의 기록에는 넣지 않는다.

QR을 가진 사람이 실제 그 학생인지까지 QR만으로 증명되지는 않는다. 교사가 배부·접속 대상을 확인하며 실제 운영 전 만료 시간·재발급·공용 기기 정책을 확정한다. 시안은 가상 학생과 QR 자리 표시만 사용하며 촬영·인증·서버 저장을 구현하지 않는다.

## 4. 앱·활동 정의 등록

앱은 결과를 보내기 전에 아래 정의를 등록한다. 서버는 앱 등록과 버전별 활동 정의를 검증한다. 자유 텍스트 제목으로 활동을 묶지 않는다.

- 앱: `appId`, 표시 이름, 개발 담당자, 허용 출처 목록
- 활동: `activityId`, `activityVersion`, 제목, 교과 코드, 학습 목표 코드와 설명
- 지표: `metricId`, `definitionVersion`, 이름, 자료형, 단위, 범위, 산출식, 분모 의미
- 해석 방향: `higher`, `lower`, `none` 중 하나. 방향이 있어도 자동으로 능력 향상을 단정하지 않음
- 비교 조건: 지표별 필수 조건 키, 조건의 값 형식과 의미
- 결과물: 허용 첨부 종류, 기록 요약 작성 기준

교과·목표 코드는 공통 사전에 등록한다. 자체 코드는 앱 이름 공간으로 구분하고 교사가 확인한 매핑 전에는 다른 앱의 지표와 합치지 않는다. 같은 표시 이름을 사용해도 다른 지표 버전은 자동 비교하지 않는다.

## 5. 결과 봉투

아래는 가상 ID를 사용한 **초안 wire format**이다. `schemaVersion`은 연동 규약의 버전이며 아침교실 IndexedDB의 버전과 별개다.

```json
{
  "schemaVersion": "0.1-draft",
  "resultId": "demo-result-002",
  "sessionId": "demo-session-002",
  "bindingId": "demo-binding-001",
  "appId": "example.counting",
  "appVersion": "1.0.0",
  "activityId": "count-objects",
  "activityVersion": "1.0",
  "title": "가을 열매를 세어요",
  "subjectCodes": ["math"],
  "objectiveCodes": ["example.counting.one-to-one"],
  "startedAt": "2026-10-24T01:00:00Z",
  "completedAt": "2026-10-24T01:05:00Z",
  "timeZone": "Asia/Seoul",
  "completion": "completed",
  "summary": "그림 단서를 사용해 첫 시도에 10문항 중 8문항을 맞혔어요.",
  "conditions": {
    "numberRange": "1-10",
    "itemSetVersion": "autumn-1",
    "attemptBasis": "first",
    "supportType": "visual",
    "supportCount": null
  },
  "metrics": [
    {
      "metricId": "first-correct",
      "definitionVersion": "1",
      "status": "measured",
      "value": 8,
      "unit": "item",
      "denominator": 10,
      "provenance": "app_observed"
    },
    {
      "metricId": "independent-performance",
      "definitionVersion": "1",
      "status": "not_measured",
      "reason": "교사의 도움 여부를 앱이 관찰하지 않았어요.",
      "provenance": "app_observed"
    }
  ],
  "artifacts": [],
  "extensions": {}
}
```

### 필드 제약

- 위 필드 중 `startedAt`과 `extensions`는 선택이다. 나머지는 필수이며 `metrics`, `artifacts`는 빈 배열도 허용한다. `objectiveCodes`는 등록한 목표를 최소 하나 포함한다.
- `completion`: `completed` 또는 `partial`. 미완료는 실패나 0점과 다르다. 중간 응답마다 결과를 제출하지 않고 활동의 의미 있는 완료/중단 시점에 제출한다.
- 날짜는 UTC 시각과 IANA 시간대를 함께 기록한다. 서버는 `receivedAt`을 별도로 부여한다. 날짜별 보기는 수행 시각을 시간대에 맞춰 계산하며 서버 도착일로 바꾸지 않는다. 기기 시각 이상은 표시하고 교사의 정정 이력을 남긴다.
- `metrics.status`: `measured`, `not_measured`, `not_applicable`. `measured`는 등록 자료형과 맞는 `value` 필수. 나머지는 `value`를 생략하고 `reason`을 넣는다. 누락·null을 0으로 바꾸지 않는다.
- 수치 지표는 유한한 값만 허용한다. 개수는 정수, 정답 개수는 0~분모 범위이며 분모는 양의 정수다. 문자열·선택형 지표의 허용값도 정의에 등록한다.
- `provenance`: `app_observed`, `student_reported`, `teacher_entered`. 앱 로그와 교사 판단을 구분한다. AI 추정은 학생의 원본 수행 지표로 제출하지 않는다.
- `conditions`는 활동 정의에 등록한 키만 사용한다. 비교 필수 조건이 없거나 측정하지 못한 경우 저장은 가능해도 비교에서는 제외한다. 값 `null`은 ‘확인하지 못함’이며 도움 없음과 다르다.
- `summary`는 관찰 사실 요약이다. 진단·성격·동기·정서 상태를 추정하지 않는다. 성공만 선택적으로 전송하지 않고 유효한 활동 결과를 일관되게 남긴다.
- `extensions`는 앱 이름 공간 아래의 JSON 데이터만 허용한다. 실행 코드·HTML·인증 정보·무관한 개인정보를 넣지 않는다. 공통 분석에는 별도 정의·승인 없이 사용하지 않는다.

## 6. 첨부 결과물

점수가 없는 활동은 `metrics: []`와 작품으로 제출할 수 있다. 이미지·PDF·음성 등은 JSON에 base64로 넣지 않고 별도 업로드한다.

1. 인증된 학생 세션으로 업로드 허가를 요청한다.
2. 허가된 업로드 대상에 파일을 보낸다. 서버는 실제 MIME·파일 크기·내용 안전성을 검사한다.
3. 업로드 완료 후 서버가 반환한 `artifactId`를 결과에 연결한다.
4. 최종 결과 저장 시 서버가 첨부의 소유 학생·앱·완료 상태를 검사한다. 다른 학생의 첨부 참조를 거부한다.

첨부 참조 예시:

```json
{
  "artifactId": "demo-artifact-001",
  "kind": "image",
  "mimeType": "image/png",
  "byteSize": 12345,
  "title": "가을 작품",
  "altText": "학생이 완성한 가을 주제 작품"
}
```

앱이 제출한 임의 URL을 서버가 자동 다운로드하지 않는다. 영구 공개 링크 대신 권한 검사 후 제한된 열람을 제공한다. 불필요한 사진 위치 메타데이터는 제거한다. 결과에 연결되지 않은 업로드는 별도 정리 대상이다. 허용 확장자·파일당/학생당 용량·보관 기간은 서비스 정책으로 확정한 뒤 배포한다.

## 7. 전달과 재전송 계약

아래는 개념적 인터페이스다. 실제 URL·HTTP 메서드·인증 헤더는 서버 명세 확정 후 연결 모듈이 담당한다.

| 연산 | 입력 | 성공 결과 |
|---|---|---|
| 연결 교환 | 제한된 연결 수단 | 학생 세션과 binding 참조 |
| 첨부 준비/완료 | 파일 정보, 업로드 결과 | 소유권이 확인된 artifact 참조 |
| 결과 제출 | 결과 봉투, 인증 세션 | 영속 저장 후 수신증 |
| 결과 상태 확인 | resultId, 인증 세션 | 본인 결과의 저장 여부와 수신증 |

수신증은 `resultId`, `receiptId`, `receivedAt`, `status: accepted | already_accepted`를 포함한다. 서버가 영속 저장을 마친 뒤만 반환한다. 처리 대기 응답은 저장 완료로 표시하지 않는다.

중복 키는 서버가 확인한 `(tenantId, appId, resultId)`다. 동일 ID·동일 내용의 재전송은 원래 수신증을 반환한다. 동일 ID에 내용이나 학생 연결이 달라지면 충돌로 거부한다. 최초 저장과 중복 판단은 원자적으로 처리한다. 결과를 고칠 때 ID를 바꿔 몰래 덮어쓰지 않는다. 정정은 새 결과 ID와 `supersedesResultId`, 정정 사유를 쓰는 명시적 절차로 처리하며 서버는 동일 소유 범위를 검사하고 이전 판본을 분석에서 중복 집계하지 않는다.

앱의 전송 상태는 `queued → sending → accepted`를 기본으로 하고 오류 시 `retry_wait`, `needs_reconnect`, `rejected`로 나눈다. 완료 직전에 전송할 결과와 소유 연결을 기기 내 대기열에 기록한다. 페이지 종료만을 유일한 전송 시점으로 삼지 않는다.

| 상황 | 처리 |
|---|---|
| 네트워크 끊김·시간 초과·일시적 서버 오류 | 같은 resultId로 간격을 늘려 재시도. 무한 반복 요청 금지 |
| 요청 제한 | 서버가 안내한 재시도 시각 준수 |
| 인증 만료 | 재연결 안내. 대기 결과는 원래 학생에게만 재전송 |
| 권한 없음 | 자동 재시도 중단, 교사에게 연결 확인 안내 |
| 자료 형식·버전 오류 | rejected, 수정 가능한 오류 표시. 성공으로 숨기지 않음 |
| 저장 후 응답 유실 | 상태 확인 또는 같은 ID로 재전송하여 원래 수신증 회수 |
| 첨부 업로드 중단 | 완료 확인 후 참조. 부분 파일을 완성 작품으로 등록하지 않음 |

화면은 ‘보내기 대기’, ‘보내는 중’, ‘아침교실에 저장했어요’, ‘다시 연결해 주세요’를 구분한다. 앱을 닫거나 브라우저 자료를 삭제하면 기기 내 대기 결과가 유실될 수 있으므로, 미전송 상태에서 기기 초기화를 유도하지 않는다. 오프라인 보관과 서버 삭제/보존은 별개 정책이다.

## 8. 아침교실의 수신·정리·변화 분석

원본 봉투·서버가 검증한 학생 연결·수신 시각을 보존하고 표시 자료와 분석 자료를 따로 만든다. 외부 문자열은 텍스트로 렌더링한다. 앱 결과에 포함된 문장을 실행 지침으로 취급하지 않는다.

- 날짜별: 수행 날짜, 교과, 앱, 활동으로 조회한다. 같은 날짜 여러 실행은 합치지 않고 각각 표시한다.
- 활동별: `(learnerId, appId, activityId)`로 모으고 버전과 비교 조건을 구분한다.
- 비교: 지표 정의 버전, 비교 필수 조건, 측정 방식이 같은 측정값만 사용한다. 앱 버전이 달라도 호환성 선언과 검증이 있어야 비교한다.
- 표시: 첫 기록·최근 기록·전체 경로·기록 수·기간·단위·제외 이유를 함께 표시한다. 정답률 변화는 퍼센트포인트와 비율 증가를 혼동하지 않는다.
- 기록 1개는 변화 판단 보류, 결측은 0점 처리하지 않는다. 점수 없는 작품은 날짜별 나란히 보기 등으로 비교한다.
- 도움 수준이나 난이도가 달라지면 별도 맥락으로 설명한다. 서로 다른 교과 점수 합산이나 학생 간 순위를 기본 제공하지 않는다.
- 분석은 ‘관찰 사실 / 조건 내 변화 / 다음 활동 제안’을 구분한다. 진단이나 능력 향상을 단정하지 않는다.

## 9. 종합의견의 경계

교과별 결과를 모아 교사 검토용 초안을 만드는 것이 목표다. 원본 수행 결과, 교사 메모, 자동 초안을 분리한다. 분석 산출물에는 학생·기간·근거 resultId 목록·비교 조건·제외 사유·생성 시각·규칙/프롬프트/모델 버전·검토 상태를 남긴다. 정정·삭제된 근거의 영향도 다시 반영한다. AI 서비스로의 학생 자료 전송은 별도 확정 사항이다.

**실제 생성 기능 연결 전에 [후속 협의](./후속-협의.md)를 읽고 사용자에게 지침·프롬프트 공동 검토를 요청한다.** 현재 시안 문구는 확정된 생성 지침이 아니다. 프롬프트에는 수신한 앱 문구를 신뢰하지 않는 데이터로 전달하며, 앱이 의견 생성 규칙을 변경할 수 없도록 한다. 교사 검토 전 자동 공개·공식 기록 확정은 하지 않는다.

## 10. 버전과 운영 전 확정 항목

필드 의미·필수값·단위·산출식·권한 모델이 바뀌면 호환성 영향을 기록하고 규약 버전을 갱신한다. 수신 서버는 지원 버전을 명시하고 미지원 버전을 오류로 반환한다. 원본 버전을 보존하며 변환한 표시 자료에 변환 버전을 기록한다.

실제 자료 연동을 시작하기 전 아래를 사용자와 확정한다. 확정 전 개발자는 가상 어댑터와 테스트 자료로 진행하며 임의 운영 서비스를 만들거나 실자료를 전송하지 않는다.

- 서버 제품·운영 소유자·실제 API 주소, 앱 등록·승인 절차
- 교사 인증, 학생 연결·해제 방식과 세션/QR 만료, 공유 태블릿 정책
- 지표·교과 사전, 정정·삭제 권한, ID·오류 코드·용량 제한
- 자료 보관 기간·삭제·교사 내보내기·백업 복원·오프라인 대기 자료 정책
- 개인정보 안내·학교 운영 절차, 서비스의 실제 권한 검증과 감사 로그 범위
- 첫 연결 앱과 실제 결과 사례, 종합의견 지침·프롬프트 공동 검토

## 무료 시험 운영의 첨부 제한

첫 시험의 압축·용량·한도 초과 처리는 [무료 시험 운영·용량 설계](./무료-시험운영-용량-설계.md)를 따른다. 초기 기본값은 이미지 목표 200KB, 최종 상한 500KB, 학급별 누적 파일 100MB다. 서버가 학급·전체 예산을 원자적으로 예약하고 실제 크기를 검증한다. 용량 초과는 저장 성공이 아니며 필수 작품을 누락한 채 완료 처리하지 않는다. 대기 결과는 원래 학생 연결을 유지한다. 첫 시험은 이미지·텍스트만 지원한다. 아직 운영에 적용하지 않았다.
