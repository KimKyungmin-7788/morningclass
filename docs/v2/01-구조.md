# 아침교실 v2 — 구조와 규칙

React + TypeScript + Vite + Zustand. 시험은 Vitest.

## 실행

```bash
npm install
npm run dev      # http://localhost:3000/app.html (기존 앱은 /legacy.html)
npm run check    # 타입 검사 + 시험
npm run build    # dist/ 로 빌드
```

## 규칙

1. **기능은 폴더 하나.** `src/features/<이름>/manifest.ts(x)` 가 카드를 등록한다. `registry.ts` 는 고치지 않는다.
   카드가 어느 칸에 놓일지는 배치표가 정한다 — 학급 설정(`options.layout`)에 저장하고, 없으면 `layout/model.ts` 의 기본 배치. 새 카드는 기본 배치에 넣지 않으면 보관함에 들어간다.
   수정 모드는 카드를 길게 누르고 확인 문제(곱셈)를 맞히거나, 관리 → 학급설정의 '화면 배치 편집'로 들어간다 (화면에 보이는 이름은 '내 맘대로 배치'). 확인 문제는 창으로, 보관함은 진행률 줄 자리에 나온다. 수정 모드의 모양과 동작은 아이폰 홈 화면 편집(흔들림 · − 단추 · 끌어 바꾸기 · 완료/빈 곳 누르기)을 따른다.
   작은 칸(tiny·small)에서는 `CardCompact`(아이콘 + 제목 + 상태 한 줄)로 그린다. 칸에는 `data-size` 와 열 너비 `data-w`(narrow·wide)가 붙어 있어 CSS 로 모양을 맞춘다.
   카드의 높이는 카드가 아니라 칸(`SLOTS`)이 정하고, 카드는 칸 크기(`size`: tiny·small·medium·large)를 받아 모습을 바꾼다.
2. **계산과 화면을 나눈다.** 집계·파싱·쪽 나누기 같은 계산은 React 를 모르는 `.ts` 파일에 두고 `*.test.ts` 로 시험한다. 화면(`.tsx`)은 그 결과를 그리기만 한다.
3. **기능끼리 직접 부르지 않는다.** 다른 기능의 값이 필요하면 `core` 의 저장소(store)를 구독한다.
4. **저장은 `core/storage` 한 곳으로.** 기능이 `localStorage`·IndexedDB 를 직접 건드리지 않는다. 기존 `mc_` 자료는 읽기만 한다(지우지 않음).
5. **학생은 고유 번호(id)로 참조한다.** 이름을 키로 쓰지 않는다.
6. **모양은 기존과 같게.** 색·글자·모서리·부품·말투 규칙은 저장소 맨 위 `DESIGN.md` 를 따른다. 기존 클래스 이름을 그대로 쓰면 `legacy.css` 가 적용된다. 옮긴 기능의 스타일은 그 기능 폴더의 CSS 로 떼어 낸다.
7. **기존 앱(`main`)은 버그 수정만.** 수정이 생기면 `v2` 에 병합하고, 이미 옮긴 기능이면 새 코드에도 반영한다.
8. **학생 활동은 소리 안내를 포함한다.** 계절·날씨·분류·아이템 같은 학생용 선택지는 `core/sound.ts`의 `playSound`와 `core/tts.ts`의 `speak`로 이름 읽기와 짧은 효과음을 제공한다. 음소거, 중복 재생 방지, 성공 후 완료 안내를 지키고 새 카드에도 적용한다. 상세 기준과 검수 항목은 `DESIGN.md`의 ‘학생 활동의 TTS·효과음’을 따른다.
9. **단계가 끝나면** `npm run check` → 화면 확인 → 점검표 갱신 → `v2` 에 커밋·푸시.

## 설정과 기능별 편집 화면 (2026-10-20)

### 글꼴

관리·백업·시간표·영상·상단 버튼은 앱 공통 페이퍼로지(`--font-ui`)를 사용한다. 별도의 Pretendard 글꼴을 지정하지 않는다. 제목은 `--fw-title`(800), 버튼·메뉴는 `--fw-label`(600), 설명은 `--fw-body`(400)를 기준으로 한다.

### 상단 도구

상단 도구는 ‘소리 켜짐/꺼짐’과 ‘관리’ 두 개만 둔다. 기능 제안은 관리 사이드바 아래 ‘의견 보내기’로 옮긴다. 별도의 지난 기록 버튼은 제거하고, 날짜 선택으로 해당 날짜의 기록을 확인한다. 배치 편집은 카드 길게 누르기와 관리 → 학급설정 → ‘화면 배치 편집’에서 시작한다. 첫 화면 안내와 관리 사이드바에 ‘카드를 꾹 누르면 화면 배치를 바꿀 수 있어요’ 문구로 동작을 알린다. 편집 완료는 배치 보관함의 완료 버튼을 사용한다.

### 관리 사이드바

메뉴 순서는 **학급설정 → 학생설정 → 출결대시보드 → 백업**이다. 시간표와 영상 관리는 각 카드의 모달에서 제공한다.

사이드바는 옅은 회색 바탕에 동일한 스타일의 Phosphor 아이콘, 짙은 메뉴명, 작은 설명을 배치한다. 선택 항목은 흰 배경·파란 글자·왼쪽 강조선으로 구분한다. 데스크톱에서는 238px 사이드바와 본문을 나누고, 700px 이하에서는 메뉴를 상단 2열로 배치한다. 키보드 초점도 표시한다.

학급·학생 편집은 설정 창의 저장 버튼으로 반영한다. 시간표와 영상에서 즉시 저장한 옵션은 설정 창을 저장할 때 이전 값으로 덮어쓰지 않는다.

### 백업 화면

마지막 백업 시각만 표시하고 기록 일수·사용 용량 통계와 반복 안내 상자는 생략한다. ‘백업 다운로드’를 유일한 기본 강조 버튼으로 두며, 모든 학급의 자료를 파일로 저장한다. ‘파일 선택’은 복원 전에 파일명·학급 수·기록 수와 변환 시 주의사항을 보여준다. 복원 시에는 현재 모든 학급의 자료가 교체된다는 안내와 최종 확인을 거친다. 삭제 기능은 ‘자료 정리’ 접힘 영역에 두고, 기존 삭제 확인 절차를 유지한다. 백업 탭에서는 설정 창 하단의 취소·저장 버튼을 숨긴다.

### 시간표 모달

‘오늘 시간표’와 ‘요일별 미리 입력’을 전환한다. 미리 입력 화면은 월~금 5열 × 1~7교시 7행의 **주간 표**이며, 요일 탭을 오가며 긴 입력칸을 채우는 방식은 사용하지 않는다.

- 과목을 선택하고 여러 칸을 눌러 같은 과목을 연속 입력한다.
- ‘직접 입력’에서는 과목 자동완성을 사용하고 Tab 키로 다음 칸으로 이동한다.
- ‘지우개’에서는 누른 칸만 비운다.
- 요일 복사는 원본·대상 요일을 선택한다. 대상에 내용이 있으면 덮어쓰기 전에 확인한다.
- 과목 추가·숨기기·아이콘 변경은 아래 ‘과목 관리’ 접힘 영역에서 제공한다.
- 수정은 학급별로 즉시 저장한다. 좁은 화면에서는 표를 가로로 스크롤한다.

‘자동 불러오기’는 학급별 옵션 `options.timetableAutoLoad`에 저장한다. 시간표 모달이 닫힌 상태에서, 선택한 날짜의 시간표가 아직 작성되지 않았고 해당 요일의 미리 입력한 과목이 있으면 채운다. 기존 작성 기록과 사용자가 저장한 빈 배열은 유지한다. 주말과 미입력 요일은 자동으로 채우지 않는다. ‘요일 시간표 불러오기’ 버튼으로 수동으로 가져올 수도 있으며, 현재 배치가 있으면 교체 전에 확인한다.

오늘 시간표는 마우스·터치 모두 카드 전체를 잡아 끄는 방식을 유지한다. 교과 보관함은 카드의 위아래 간격 8px와 위아래 여백 10px를 유지하고, 좌우 간격과 좌우 여백만 24px로 넓혀 빈 공간에서 손가락으로 쓸어 스크롤할 수 있게 한다. 별도의 끌기 손잡이는 두지 않는다.

### 영상 모달

모달에서 검색어를 입력하면 새 창으로 유튜브 검색을 연다. 검색 결과를 모달 안에 표시하는 방식은 아니다. 선택한 영상의 공유 링크를 가져오면 재생하며, 제목을 입력하고 ‘저장 · 기본 영상 지정’을 눌러 카드의 기본 영상을 바꾼다.

영상 목록은 이 기기의 IndexedDB에 저장되어 모달을 닫거나 새로고침해도 유지된다. 목록은 학급 공용이며 최근 50개까지 보관하고, 같은 영상은 중복하지 않는다. 카드의 기본 영상 주소·제목은 학급별 `options.video`에 저장한다. 비동기로 제목을 불러올 때는 최신 목록을 기준으로 해당 영상만 갱신한다.

### 배포 전 재검토 (2026-10-22)

유튜브 검색은 새 창 탐색으로 열어 운영 환경의 `form-action` 보안 정책과 충돌하지 않게 한다. 시간표 편집 초안은 급식 등 무관한 기록 갱신에도 유지하며, 학급·날짜가 바뀔 때만 새 편집 화면으로 시작한다. 백업 복원 성공 시 관리 창을 닫아 복원 전 편집 내용이 다시 저장되지 않게 한다. 주간 시간표·자동 불러오기·영상 목록·기본 영상의 백업 왕복 보존 시험을 추가했다.
## 학생 카드 1단계

- `features/students/manifest.tsx`는 `Header`와 `Overlay` 자리에 등록한다. registry는 바꾸지 않는다.
- `core/data/notes.ts`는 학생 기록 읽기·쓰기, `pin.ts`는 화면 잠금과 백업 복구 열쇠 확인을 맡는다.
- 저장소 v2는 `notes`, `ieps`를 추가한다. 백업 v2에는 생활표현 설정, 학생 기록 설정, 누가기록, IEP, 복구 열쇠를 넣으며 PIN 해시는 넣지 않는다.
- IEP 편집·월 목표 연결·인쇄는 1단계 화면에 넣지 않는다.

## 오늘은 어떤 옷? (2026-10-23)

`features/outfit/manifest.tsx` 카드 → 학생 선택 → `Editor.tsx` 옷 선택 → 완료. 날짜별 학생 옷차림은 `DayRecord.outfits`에 저장하고 `lastOutfitStudentId`로 마지막 완료를 가리킨다. 저장은 `core/data/outfits.ts`를 통해 트랜잭션 완료 후 화면에 반영한다. 학생 카드와 메인 카드의 합성 그림은 `core/ui/OutfitFigure.tsx`를 공유한다. 저장소·백업 스키마는 v3이며 기존 기록의 추가 필드가 없으면 미완료로 읽는다. 기존 칸은 그대로 두고 하단 바구니에서 시작한다.

## 학생별 내 얼굴 (2026-10-24)

스키마 v9의 `Student.facePhoto`는 감정·옷입히기 공용 선택 필드다. 사진이 없으면 기존 남녀 캐릭터를 유지한다. `core/ui/FaceControl.tsx`에서 파일 또는 카메라 사진을 원 안에서 이동·확대하고, 실제 아바타 미리보기를 보며 저장한다. 원본 대신 기기 안에서 자른 320×320 JPEG만 `core/data/faces.ts` → 저장소 트랜잭션으로 저장하며 백업에 포함한다. 얼굴 초기화는 사진 필드만 삭제한다. 감정 선택·남녀 캐릭터·옷차림은 변경하지 않는다. 카메라는 명시적인 클릭 뒤만 켜고 촬영·닫기·언마운트에 트랙을 해제한다. CSP의 기존 data/blob 이미지 허용을 사용하며 Permissions-Policy는 camera=(self)로 제한한다. 외부 사진 전송은 없다.

## 활동 창과 학생 파일철 (2026-10-24)

- 옷입히기는 학생 선택·날짜, 계절·날씨를 별도 줄로 나누고 되돌리기를 옷장 제목 옆에 둔다.
- 성별을 새로 선택하면 `saveEmotionAvatar` 트랜잭션에서 학생의 `emotionAvatar`·`outfitAvatar`를 함께 갱신한다. 한쪽만 저장된 학생은 다른 쪽에서도 그 값을 사용한다. 이미 양쪽 값이 다른 학생은 선택 시각이 없어 과거 순서를 추정하지 않고, 다음 성별 선택 시 양쪽을 같은 값으로 통일한다. 얼굴 사진과 옷차림은 보존한다.
- 기존 `SideSwitch`는 삭제하지 않고 숨긴다. 학생 이름은 `students/manifest.tsx`의 오른쪽 인덱스로 옮기며, 이름을 누르면 학생 카드가 왼쪽에서 펼쳐진다. 명단 순서별 파스텔 색상의 반투명 세로 탭을 화면 안쪽에 겹쳐 표시하며 본문 너비를 줄이지 않는다. 스크롤과 움직임 줄이기 설정을 지원한다.
- 수업 도구·판서는 클릭 시 `core/ui/UtilityWindow.tsx`의 `window.open`으로 작은 브라우저 창을 연다. 운영체제 제목 줄로 모니터 간 이동·크기 변경이 가능하며, 앱 상태는 부모 화면과 같은 React 저장소를 사용한다. 부모 화면을 닫으면 도구 창도 닫힌다. 새 창이 차단되면 화면 안의 이동·크기 변경 가능한 창으로 연다. 전체 화면은 별도 버튼으로 선택한다.
- 판서의 포인터 좌표는 기존 칠판 기준을 유지하고 키보드·붙여넣기 이벤트는 실제 칠판이 있는 창에 연결한다. 브라우저가 새 창을 탭으로 여는 환경에서는 일반 브라우저의 창 분리 기능을 사용할 수 있다.

## 포트폴리오 시안과 후속 협의

`features/students/PortfolioPreview.tsx`와 `PortfolioReviewPreview.tsx`는 가상 기록만 사용하는 날짜별·활동별 변화·종합의견 시안이다. 실제 자동 생성이나 저장을 연결하기 전에 반드시 [포트폴리오 후속 협의](../portfolio/후속-협의.md)를 읽고, 사용자와 종합의견 생성 지침·프롬프트를 함께 검토한다. 현재 고정 예시를 확정된 생성 규칙으로 취급하지 않는다.

교육 웹앱의 결과 전송·수신을 개발할 때는 [공통 연동 규약](../portfolio/공통-연동-규약.md)과 [웹앱 개발 지침](../portfolio/웹앱-개발-지침.md)을 먼저 읽는다. 현재는 설계 초안이며 운영 서버/API/SDK는 구현되지 않았다.
